# API reference (Member 2 backend)

One page with every endpoint. Details live in the linked documents. Base URL in development: `http://127.0.0.1:8000`.
Interactive documentation is generated by FastAPI at `/docs`; the machine-readable contract is at `/openapi.json`.

## Endpoints
| Endpoint | Purpose | Rate limited | Details |
|---|---|---|---|
| GET /health | liveness + whether Gemini/database are configured (never their values) | no | below |
| GET /health/ready | readiness: the database answers `SELECT 1` | no | below |
| POST /api/knowledge/retrieve | text -> candidate concepts -> supported mudras/movements with sources and limitations | no | api_knowledge.md |
| GET /api/mudras | list mudras (filters: category, limit 1-200, offset) | no | api_knowledge.md |
| GET /api/mudras/{mudra_id} | one mudra | no | api_knowledge.md |
| GET /api/movements | list movements (none verified yet, so empty) | no | api_knowledge.md |
| GET /api/practice/references | list only classifier/reference-sequence-backed practice targets; currently empty | no | project_audit.md |
| POST /api/practice/sessions | create a persisted attempt for an existing mudra or movement | no | practice workflow |
| POST /api/practice/sessions/{session_id}/video | bounded MP4/WebM upload and frame decode; returns structured 503 until artifacts/runtime are available | no | practice workflow |
| POST /api/practice/sessions/{session_id}/evaluate | evaluate an uploaded attempt; structured unavailable response until runtime is enabled | no | practice workflow |
| GET /api/practice/sessions/{session_id}/results | retrieve stored result or explicit null for an unevaluated attempt | no | practice workflow |
| GET /api/reference-sequences | teacher-verified sequence metadata only | no | reference workflow |
| POST /api/reference-sequences | reviewer-token protected candidate/verified sequence ingestion | no | reference workflow |
| GET /api/progress | persisted sessions/results/feedback, development/test scope only until user auth exists | no | project_audit.md |
| POST /api/tutor/explain | RAG tutor: retrieval + Gemini explanation, always with the retrieved records | yes (shared) | rag_pipeline.md |
| POST /api/feedback/generate | evidence-grounded feedback for a stored session; reuses stored feedback unless `regenerate` | yes (shared) | feedback.md |
| GET /api/feedback/{session_id} | latest stored feedback, no generation | no | feedback.md |

"Shared" = the tutor and feedback endpoints share one per-IP budget (`TUTOR_RATE_LIMIT_PER_MINUTE`, default 20) because both can call the paid Gemini API.
There is **no login yet**. The progress route is disabled in production so globally shared local
history is not presented as private user data. Development/test history is installation-wide.
The practice API persists attempts, validates bounded uploads, decodes frames, and returns
explicit dependency/runtime errors. It does not fabricate results: model and task artifacts are
absent, and the native MediaPipe runtime has not passed a deployment smoke test.

## Request and response summaries
**POST /api/knowledge/retrieve** - `{text (1-1000), include_unverified?, include_keyword_matches?}` ->
`{original_text, concepts[{concept, status, references[...], contains_unverified, note}], supported_count, unsupported_count, warnings, disclaimer}`.
A reference carries `record_id`, `name`, `meaning`, `usage`, `match_type`, `verification_status`, `source`, `mapping_source`, `limitations`.

**POST /api/tutor/explain** - same request -> `{original_text, tutor{mode, explanation, model, fallback_reason, notice}, retrieval, disclaimer}`.
`tutor.mode` is `ai` or `knowledge_only`.

**POST /api/feedback/generate** - `{session_id, regenerate?}` ->
`{mode, session_id, reference, evidence_level, is_mock, feedback{overall_summary, observations, suggestions, limitations}, supporting_evidence[], model, fallback_reason, notice, saved, reused, disclaimer}`.
`mode` is `ai` or `evidence_only`. The request carries no evaluation data; anything extra is ignored.

**GET /health** - `{status, service, version, environment, gemini_configured, database_configured}`.
**GET /health/ready** - `{status: "ready", database: "ok"}` or a 503.
**GET /api/practice/references** - `[]` until both a compatible trained model and validated
reference sequences are installed.
**GET /api/progress** - `{scope: "shared_development", sessions: [...]}` from the configured
SQL database; production requests are disabled until authenticated ownership is implemented.
Unevaluated rows have null prediction, DTW, and feedback fields.
**POST /api/practice/sessions** - `{reference_id}` -> `{session_id, reference_id, status, created_at}`.
**POST /api/reference-sequences** - version 1 sequence JSON; requires `X-Reference-Review-Token`.
Verified records also require `REFERENCE_REVIEWER_IDENTITY` to match `reviewer_identity`.
Candidate records are stored but never listed as usable references.

## Status codes and errors
| Code | Meaning |
|---|---|
| 200 | success (also when Gemini failed: check `mode`) |
| 403 | unverified records requested but `ALLOW_UNVERIFIED_RECORDS` is false |
| 404 | not found (mudra, session, stored feedback). A hidden unverified mudra gives the same 404 as a missing one |
| 422 | invalid input; evaluation problems carry a `code` (invalid_session_id, malformed_result, unsupported_version, unknown_reference) |
| 429 | rate limit; `Retry-After` header |
| 500 / 502 | server-side inconsistency (`mock_data_in_real_store`, `session_mismatch`) |
| 503 | database, multipart dependency, evaluator artifact/runtime, reviewer intake, or production identity unavailable |
Error bodies: `{"detail": "..."}` (plus `"code"` for evaluation errors). FastAPI's own validation errors use a list in `detail`.
Messages never contain stack traces, SQL, connection strings or keys.
