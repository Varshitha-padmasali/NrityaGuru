# NrityaGuru — Frontend

Next.js + React + TypeScript + Tailwind CSS frontend for **NrityaGuru**, an AI-assisted
Bharatanatyam learning and practice-evaluation system. It handles the UI, the browser
camera and recording workflow, and all communication with the FastAPI backend.

> The frontend never calculates scores or invents content. Every mudra, explanation,
> prediction, DTW value and piece of feedback on screen comes from the backend.

## Prerequisites
- Node.js **20.9+** (tested with Node 22)
- npm 10+
- A recent Chrome, Edge, Firefox or Safari with a webcam

## Setup
```bash
cd frontend
npm install
cp .env.example .env.local      # Windows: copy .env.example .env.local
```
Edit `.env.local` if your backend isn't on `http://localhost:8000`.

## Run
```bash
npm run dev          # http://localhost:3000
```
The dot in the header shows whether `GET /health` on the backend answers.

### Developing before the backend exists (mock mode)
Set `NEXT_PUBLIC_USE_MOCK_API=true` in `.env.local` and restart `npm run dev`.
A yellow banner then appears on every page and all data is obvious placeholder text
("Sample Mudra A", "[Mock …]"). **Turn it off for demos, screenshots and evaluation.**

### Home-page images — generate them with Gemini
The home page opens with a **full-screen slideshow of a dancer moving through the eight
steps of a recital (the margam)** — Pushpanjali, Alarippu, Jatiswaram, Shabdam, Varnam,
Padam, Tillana, Mangalam — with a caption for each step (slots `seq1`–`seq8`). Frames 2–8
are generated with frame 1 as a reference image, so the same dancer appears in every step:
generate `seq1` first and regenerate it until you love it. There are also image slots for
the shloka section and four gallery tiles.
You can fill them with **photorealistic images generated by Gemini** (`gemini-nano-banana-2.1`):

1. Get a key at https://aistudio.google.com/apikey and add it to `.env.local`:
   ```
   GEMINI_API_KEY=your-key
   ```
   (Server-side only — **never** name it `NEXT_PUBLIC_…`, or it would be sent to the browser.)
2. Either run
   ```bash
   npm run images:generate                 # all slots without an image
   npm run images:generate -- hero shloka  # regenerate specific slots
   npm run images:generate -- --force      # regenerate everything
   ```
   or open **http://localhost:3000/studio** while `npm run dev` is running: see each slot's
   prompt, edit it, click **Generate**, and regenerate until you like it.
3. Images are saved to `public/images/generated/` and recorded in `lib/photos.json`; the site
   uses them automatically. Commit them so they also work offline and in deployment.

Prompts live in `lib/image-prompts.json`. All generated images show an
**"AI-generated with Gemini"** label (Gemini also embeds an invisible SynthID watermark).
They depict a fictional dancer and are **decoration only** — AI images often get hands
wrong, so never use them as mudra references; those come from the verified knowledge base.
Image generation may need billing enabled on your Google AI Studio project.

**Fallbacks:** a slot without a generated image shows a free-licence stock photo
(Pexels/Unsplash, credited; `npm run photos:download` saves copies for offline use), and
if that can't load either, the original illustrated dancer — never a broken image.
The `/studio` page and its API are disabled in production builds.

## How the camera workflow works
1. **Permission only on click.** `useCamera.start()` calls `getUserMedia({ video, audio: false })`
   only after the learner presses *Enable camera*. Camera access requires `https://` or
   `http://localhost`.
2. **Recording.** `useMediaRecorder` picks a supported format with
   `MediaRecorder.isTypeSupported()` (WebM VP9 → VP8 → MP4), shows elapsed time, and stops
   automatically at the limit (8 s by default).
3. **Review / retake.** The clip is kept only in memory as a Blob + temporary object URL.
   Retake, reset and leaving the page revoke the URL — nothing goes to localStorage.
4. **Submit.** Only when the learner presses *Submit*: create session → multipart upload with
   progress (XHR) → evaluate → poll if still processing → open the results page.
5. **Cleanup.** Leaving the page stops every camera track (the camera light turns off),
   cancels uploads and clears timers.

A small state machine (`components/practice/practiceMachine.ts`) blocks invalid actions:
no recording before the camera is ready, no submit without a recording, no double submit.

## Error handling
All API failures become an `ApiError` with a `kind` (network, timeout, validation, not_found,
too_large, unavailable, http, malformed, aborted) and a friendly message via `describeError()`.
Responses are checked at runtime by `lib/validators.ts`, so a schema mismatch shows a clear
"malformed response" error instead of a crash. A Gemini outage (503) never hides retrieval
or evaluation results — the AI panels show their own retry.

## Known limitations
- The contract in `docs/api-contract.md` is a proposal; field names must be confirmed with the backend.
- No authentication yet; development progress is installation-wide and visibly labelled shared. Production progress/session/result endpoints are disabled.
- Safari can record MP4/QuickTime; backend upload support includes MP4, WebM, and QuickTime containers when required dependencies are installed.
- The live preview is mirrored for comfort; the uploaded recording is not mirrored.
